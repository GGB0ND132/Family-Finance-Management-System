# 家庭收支管理系统前端开发文档

**版本：** v1.0  
**依据：** `docs/详细设计.md`、`frontend/FRONTEND_TODO.md`、`frontend/DESIGN.md`  
**技术基线：** React + TypeScript + Vite、React Router、Axios、TanStack Query、Zustand、Ant Design、ECharts/Recharts

## 1. 前端目标与边界

前端负责页面渲染、交互校验、请求状态和用户体验；认证、家庭隔离、权限、金额计算和事务必须以后端为准。Mock 数据只用于页面演示，不能代替 API。

统一约定：

- API 前缀为 `/api/v1`，Axios 实例统一注入 JWT。
- 当前家庭只保存在 `currentFamilyId`；GET 使用 `family_id` 查询参数，写请求在 JSON 或 FormData 中携带 `family_id`。
- 个人/家庭业务页使用 `scope=personal|family`，状态写入 URL；个人首页 `/personal` 和家庭首页 `/family-dashboard` 是两个独立入口。
- 金额使用字符串或 Decimal 兼容类型接收，显示固定两位小数；禁止前端使用浮点数进行业务计算。
- 时间传输 ISO 8601，显示 `YYYY-MM-DD HH:mm`，精确到分钟。
- 所有页面必须覆盖加载中、空数据、接口错误、无权限、提交中和成功反馈。

## 2. 推荐目录与职责

```text
frontend/src/
├── api/              # Axios 实例、API 函数、请求/响应类型
├── components/       # MoneyText、ScopeToggle、EmptyState、ConfirmAction 等
├── features/         # 按业务组织表单、表格和查询 hooks
├── layouts/          # AuthLayout、AppLayout
├── pages/            # 登录、家庭、账户、流水、转账、预算、报表页面
├── router/           # 路由和 ProtectedRoute
├── stores/           # authStore、familyStore、queryStore
├── hooks/            # useDataScope、useMembers、useAccounts 等
├── types/            # 领域类型和 API 类型
└── styles/           # 主题、响应式和全局样式
```

请求层统一处理：Token 注入、401 清理登录态、错误解析、请求取消、重复提交保护和 Blob 错误响应解析。页面不得直接拼接 Axios 请求或自行定义与 API 不一致的字段。

## 3. 双人阶段分工

以下使用“前端成员 1/2”表示两位同学，实际执行时替换为姓名。两人共享 `types/`、`api/` 和设计令牌，但每个页面由一人主责，另一人负责评审和联调。

### 3.1 P1：核心页面与交互

| 成员 | 主责任务 | 交付物 | 协作点 |
|---|---|---|---|
| 前端成员 1 | 工程底座、认证、家庭、账户和分类 | Axios/Query/Zustand、路由守卫、登录注册、家庭切换/成员管理、账户 CRUD、分类管理、统一表单组件 | 先与后端确认认证、权限和基础类型；提供成员/账户/分类 hooks |
| 前端成员 2 | 流水、转账、预算和报表基础页 | 流水列表/筛选/抽屉、转账表单、预算页、个人/家庭首页和报表基础图表 | 依赖成员 1 的请求层和选择器；与后端确认余额、scope、分页响应 |

**P1 验收：** 注册登录后可创建家庭、建账户/分类、记账、转账、设置预算并查看首页；表单校验、加载/空状态和 401/403/409 提示完整。

### 3.2 P2：数据交换与质量

| 成员 | 主责任务 | 交付物 | 协作点 |
|---|---|---|---|
| 前端成员 1 | 导入和导出流程 | 三步导入向导（范围/账户 -> 上传映射 -> 预览确认）、错误/重复行展示、CSV/XLSX Blob 下载 | 与后端确认 FormData 字段、批次状态、Content-Disposition 和错误 Blob |
| 前端成员 2 | 体验完善、响应式和测试 | 移动端布局、表格/筛选/分页优化、统一错误边界、权限空状态、组件测试和主要路由验收 | 汇总两个成员页面，执行 `tsc`、lint、build 和端到端联调 |

**P2 验收：** 导入预览和确认可用，导出文件可下载；主要页面在桌面和移动断点正常，错误和权限反馈一致。

### 3.3 P3：可选扩展与交付

| 成员 | 主责任务 | 交付物 | 协作点 |
|---|---|---|---|
| 前端成员 1 | 定期账单/凭证附件（择一或均做） | 规则管理、待确认流水，或附件上传/预览/删除组件 | 复用流水表单和文件校验；确认后端权限和大小限制 |
| 前端成员 2 | 平台治理和交付材料 | 审计记录查看、刷新 Token 状态、异步导入进度（按后端能力选做）；用户手册截图和演示流程 | 与后端确认轮询、错误码和部署环境；整理最终验收清单 |

**P3 验收：** 所选扩展具备路由、类型、错误处理、测试和使用说明，且不改变个人/家庭统计口径。

### 3.4 双人协作规则

1. 页面开发前先在 `api/types` 中确定请求和响应类型，接口变更必须同步 API 文档。
2. 每个功能至少包含成功、加载、空数据、失败、无权限、重复提交六类状态。
3. 合并前执行 `npx tsc -b`、`npm run lint`、`npm run build`；主流程由非主责成员复测。
4. 组件库调用集中在 `components/` 和 features 中，页面不散落主题色、金额和时间格式化逻辑。

## 4. 页面与接口映射

| 页面 | 主要接口 | 关键状态 |
|---|---|---|
| 登录/注册 | `/auth/register`、`/auth/login` | submitting、401、用户名重复 |
| 个人首页 | `/reports/personal/daily`、`/reports/personal/summary` | 日期、零数据、个人资产 |
| 家庭首页 | `/reports/family/summary`、`/reports/family/by-member` | 月份、成员对比、预算 |
| 账户 | `/accounts` | personal/family、销户、余额非零 |
| 分类 | `/categories` | 收入/支出 Tabs、软删除 |
| 流水 | `/transactions` | 分页筛选、方向分类、余额更新 |
| 转账 | `/transfers` | 双账户、事务失败、总资产不变 |
| 预算 | `/budgets/{month}` | 总预算、分类项目、预警 |
| 导入/导出 | `/imports/*`、`/exports/transactions` | 预览、重复行、Blob 下载 |

## 5. 前端验收清单

- [ ] 所有 API 请求均通过统一 `apiClient`，401 自动退出并跳转登录。
- [ ] 个人查询不允许通过前端传入任意成员冒充身份；家庭切换清理旧缓存。
- [ ] 收入/支出分类、销户账户、金额和时间均有前端校验，后端错误仍可正确展示。
- [ ] 转账不显示为收入/支出；个人报表不渲染成员对比。
- [ ] CSV/XLSX 错误 Blob 会解析统一错误 JSON，不出现浏览器下载乱码。
- [ ] 完成桌面/移动端主要路由验收和键盘可操作性检查。
