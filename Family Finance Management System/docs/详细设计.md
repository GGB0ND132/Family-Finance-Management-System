# 家庭收支管理系统详细设计

**版本：** v2.0  
**对应文档：** `docs/需求分析.md`、`docs/系统设计.md`  
**适用范围：** React + TypeScript + Vite + Ant Design；FastAPI + SQLAlchemy + MySQL 8

## 1. 通用约定

### 1.1 领域枚举

| 枚举 | 值 | 用途 |
|---|---|---|
| `MemberRole` | `ADMIN`、`MEMBER` | 家庭成员角色 |
| `AccountType` | `CASH`、`BANK_CARD`、`ALIPAY`、`WECHAT`、`CREDIT_CARD`、`OTHER` | 账户类型 |
| `TransactionType` | `INCOME`、`EXPENSE` | 收入或支出流水方向 |
| `CategoryType` | `INCOME`、`EXPENSE` | 分类适用方向 |
| `ImportFileType` | `CSV`、`XLSX` | 外部账单文件格式 |
| `ImportBatchStatus` | `PREVIEWED`、`CONFIRMED`、`FAILED` | 导入批次处理状态 |
| `ImportRowStatus` | `VALID`、`INVALID`、`DUPLICATE`、`PENDING_CONFIRM` | 导入预览行状态 |

账户不设置 `ACTIVE`/`DISABLED` 一类用户控制状态。`accounts.closed_at` 为非空时表示账户已销户，只可查看历史记录，不能再产生新流水或转账。

### 1.2 公共后端组件

| 组件 | 完成内容 |
|---|---|
| `Settings` | 从 `.env` 读取数据库、JWT、CORS、文件大小限制等配置 |
| `get_db` | 创建和关闭 SQLAlchemy Session；发生异常时回滚 |
| `get_current_user` | 解析 JWT 并获得当前用户 |
| `require_family_member` | 校验当前用户属于目标家庭 |
| `require_family_admin` | 校验当前家庭成员角色为管理员 |
| `ApiResponse` | 统一成功响应结构 |
| 异常处理器 | 将领域异常转为 400、401、403、404、409 响应 |
| `Pagination` | 统一 `page`、`page_size`、`total`、`items` 结构 |
| `MoneyService` | 以 `Decimal` 计算并在事务内应用或撤销账户余额影响 |

### 1.3 公共前端组件

| 组件 | 完成内容 |
|---|---|
| `AppLayout` | 顶部栏、当前家庭切换、个人/家庭视图导航、退出登录 |
| `ProtectedRoute` | 无 Token、用户失效或未选择家庭时跳转到对应页面；登录成功默认跳转个人首页 |

| `ConfirmAction` | 删除流水、销户、确认导入等危险操作的二次确认 |
| `EmptyState` | 无账户、无流水、无报表时提供空状态与入口 |

## 2. 认证与用户模块

### 2.1 完成内容

- 注册、登录、退出、获取当前用户、修改昵称和密码。
- 用户名唯一校验、bcrypt 密码哈希、JWT 签发与校验。
- 前端登录状态持久化和 401 后自动清理。

### 2.2 数据表与接口

`users(id, username, password_hash, nickname, created_at, updated_at)`。

| 方法 | 路径 | 请求重点 | 返回重点 |
|---|---|---|---|
| `POST` | `/api/v1/auth/register` | `username,password,nickname` | 用户基础信息 |
| `POST` | `/api/v1/auth/login` | `username,password` | `access_token,token_type,user` |
| `GET` | `/api/v1/users/me` | JWT | 当前用户 |
| `PATCH` | `/api/v1/users/me` | `nickname` | 更新后的用户 |
| `PATCH` | `/api/v1/users/me/password` | `old_password,new_password` | 操作成功 |

### 2.3 页面、校验与测试

登录页和注册页使用 Ant Design `Form`，密码不得少于 8 位，注册页必须校验两次密码一致。用户名重复返回 409；密码错误统一返回“用户名或密码错误”，不暴露用户名是否存在。登录成功后路由跳转 `/personal`；若用户没有家庭，跳转 `/family` 的创建/加入界面，选择家庭后再跳转 `/personal`。测试应验证密码不以明文存储、JWT 缺失或过期时不能访问受保护接口，以及登录后的跳转逻辑。

- 保证每个家庭始终至少有一名管理员。

### 3.2 数据表与接口

families(id, name, owner_id, invite_code, invite_expires_at, created_at, updated_at)

| `POST` | `/api/v1/families/join` | 登录 | 使用邀请码加入 |
| `PATCH` | `/api/v1/families/{id}` | 管理员 | 修改家庭名称 |

## 4. 账户模块

### 4.1 完成内容

- 新增、查询、编辑账户，并为每个账户指定所属家庭成员。
- 按成员展示账户余额和个人资产，按家庭汇总未销户账户余额。
- 删除无历史账户；对已有流水或转账的账户执行销户，且删除/销户前账户余额必须为 0。

### 4.2 数据表与接口

```text
accounts(
  id, family_id, owner_member_id, name, type,
  initial_balance DECIMAL(12,2), current_balance DECIMAL(12,2),
  remark, closed_at, created_at, updated_at
)
```

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| `GET` | `/api/v1/accounts?family_id={id}&owner_member_id={id}` | 成员 | 账户列表与余额 |
| `POST` | `/api/v1/accounts` | 账户所属人/管理员 | 创建账户 |
| `PATCH` | `/api/v1/accounts/{id}` | 账户所属人/管理员 | 编辑名称、类型、所属人、备注 |
| `DELETE` | `/api/v1/accounts/{id}` | 账户所属人/管理员 | 无引用时删除；有引用时销户 |

### 4.3 页面与交互

账户页以所属成员分组显示账户名称、类型、当前余额、备注和销户标记。新增/编辑表单必须选择账户所属人；已销户账户不进入记账或转账表单的候选列表。用户点击删除时，前端先展示影响说明：无历史记录且余额为 0 将删除，有历史记录且余额为 0 将销户并保留历史；余额非 0 时提示“账户仍有资金，请先转出后再销户”，不允许继续。页面不提供停用开关。

### 4.4 校验、处理与测试

- 所属人必须是当前家庭成员；初始余额可正可负，当前余额创建时等于初始余额。普通成员仅可创建和维护所属人为自己的账户；管理员可指定或变更任何家庭成员的所属关系。
- 编辑账户所属人只改变当前资产归属，不篡改历史收支的资金归属人和录入人。
- 删除时先锁定账户并检查 `current_balance == 0.00`；余额非零返回 409 和转出提示。余额为零后再检查 `transactions.account_id`、`transfers.from_account_id` 与 `transfers.to_account_id`；存在任何关联则写入 `closed_at`，否则物理删除。
- 销户账户不计入当前个人/家庭资产，历史报表与历史明细仍可显示。
- 测试覆盖账户所属人校验、销户后不可记账/转账、无历史账户可删除和资产汇总排除销户账户。

## 5. 分类模块

### 5.1 完成内容

- 创建家庭时初始化默认收入和支出分类。
- 管理员新增、编辑、删除自定义分类；分类为历史流水或预算保留引用。
- 前端表单根据收支方向仅展示同方向分类。

### 5.2 默认分类、数据表与接口

默认支出分类为：餐饮、住宿、交通、住房、购物、娱乐、医疗、借出、还款；默认收入分类为：借入、收款、工资、奖金。

```text
categories(id, family_id, name, type, icon, color, deleted_at, created_at, updated_at)
```

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| `GET` | `/api/v1/categories?family_id={id}&type=EXPENSE` | 成员 | 查询可用或历史分类 |
| `POST` | `/api/v1/categories` | 管理员 | 新增自定义分类 |
| `PATCH` | `/api/v1/categories/{id}` | 管理员 | 修改分类名称、图标或颜色 |
| `DELETE` | `/api/v1/categories/{id}` | 管理员 | 未引用时删除；有引用时保留历史引用 |

### 5.3 页面、校验与测试

分类页通过 `Tabs` 分隔收入和支出分类，表单包含名称、方向、颜色和图标。相同家庭、相同方向的现用分类不能重名；已被使用的分类删除后不再用于新流水或预算，但历史记录保留原分类名称。测试覆盖默认分类初始化、方向匹配、重复名称和历史流水展示。

## 6. 收入与支出流水模块

### 6.1 完成内容

- 新增、查询、查看详情、编辑和删除收入、支出流水。
- 保存账户所属人之外的资金归属人和录入人，使“谁赚取/谁消费/谁录入”可追踪。
- 写入流水时同步更新账户余额；报表和预算实时按流水聚合。

### 6.2 数据表与接口

```text
transactions(
  id, family_id, account_id, category_id,
  beneficiary_member_id, recorder_user_id,
  type, amount DECIMAL(12,2), occurred_at, remark, dedup_key,
  created_at, updated_at
)
```

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/transactions` | 支持 `family_id,scope=family|personal,page,page_size,from,to,type,account_id,owner_member_id,category_id,beneficiary_member_id,recorder_user_id,min_amount,max_amount`；`scope=personal` 时成员由 JWT 自动解析 |
| `POST` | `/api/v1/transactions` | 创建收入或支出 |
| `GET` | `/api/v1/transactions/{id}` | 查询详情 |
| `PATCH` | `/api/v1/transactions/{id}` | 编辑流水 |
| `DELETE` | `/api/v1/transactions/{id}` | 删除并撤销余额影响 |

### 6.3 页面与交互

流水页的筛选区包含日期、类型、账户、账户所属人、分类、资金归属人、录入人和金额范围。新增/编辑弹窗中，选择收入或支出后过滤对应分类；必须填写金额、账户、分类、发生日期、资金归属人和备注，录入人固定显示当前登录用户。列表与详情同时显示账户所属人、资金归属人和录入人。

### 6.4 核心处理与校验

```text
apply_effect(transaction):
  INCOME  -> account.current_balance += amount
  EXPENSE -> account.current_balance -= amount

reverse_effect(transaction):
  INCOME  -> account.current_balance -= amount
  EXPENSE -> account.current_balance += amount
```

创建时锁定账户，检查账户未销户、账户/分类/成员均属同一家庭、分类方向匹配且金额大于 0，再写入流水并应用余额影响。编辑时按固定顺序锁定旧账户和新账户，撤销旧影响、验证新字段、应用新影响并更新记录。删除时锁定账户、撤销原影响、删除记录。普通成员可编辑或删除账户所属人为自己、资金归属人为自己或自己录入的流水；即使录入人为他人，只要账户或资金归属人与当前成员相关，该成员仍可编辑。管理员可维护全部流水。

### 6.5 测试点

- 收入增加、支出减少账户余额；编辑或删除后余额准确恢复。
- 账户所属人、资金归属人和录入人分别正确保存和查询。
- 销户账户、跨家庭账户、分类方向不匹配、非正金额均被拒绝。
- 个人收支按资金归属人统计，家庭收支按家庭所有流水统计。

## 7. 家庭内部转账模块

### 7.1 完成内容

- 新增、查询和删除家庭内部转账记录。
- 体现转出成员个人资产减少、转入成员个人资产增加，但不重复形成收入或支出。
- 在一个事务中完成两个账户余额变更与转账记录写入。

### 7.2 数据表与接口

```text
transfers(
  id, family_id, from_account_id, to_account_id,
  from_member_id, to_member_id, recorder_user_id,
  amount DECIMAL(12,2), occurred_at, remark, created_at
)
```

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/transfers` | 支持家庭、日期、转出方、转入方、账户筛选 |
| `POST` | `/api/v1/transfers` | 创建转账 |
| `PATCH` | `/api/v1/transfers/{id}` | 编辑转账并重新计算两个账户余额 |
| `DELETE` | `/api/v1/transfers/{id}` | 删除并反向恢复两个账户余额 |

### 7.3 页面、流程与校验

转账页表单包含转出账户、转入账户、转出方成员、转入方成员、金额、日期和备注。选择账户后自动带出所属成员，并校验与填写成员一致；转出账户不能与转入账户相同，销户账户不可选择。

```text
校验当前用户与家庭身份
  -> 校验两个账户属于同一家庭、未销户且不同
  -> 校验转出/转入成员与对应账户所属人一致
  -> 按账户 ID 顺序加行锁
  -> 转出账户余额减少，转入账户余额增加
  -> 写入 transfers，提交事务
  -> 任一步失败则全部回滚
```

转账只存入 `transfers`，不会创建两条收入/支出流水。普通成员可编辑或删除自己作为转出方、转入方或录入人的转账，转账双方均可编辑；管理员可维护全部转账。个人首页和个人报表通过转出方、转入方展示资产变动；家庭首页可单独展示转账流动，但不把它纳入家庭收支、结余和预算。测试覆盖总资产不变、个人双方资产变化、跨家庭拒绝、同账户拒绝、相关成员权限及事务回滚。

编辑转账时，在同一事务内锁定原转出/转入账户和新账户，先恢复原转账余额影响，再校验新账户未销户、双方成员归属和金额，应用新影响并更新转账记录；任一步失败全部回滚。

## 8. 个人首页、家庭首页与报表模块

### 8.1 完成内容

- 个人首页默认展示当前成员当天的收支、转账和账户变动，并展示个人资产和当天统计。
- 家庭首页展示当月家庭收支、结余、总资产、预算和成员对比。
- 分别提供个人报表和家庭报表，保证统计口径互不混淆。

### 8.2 页面与接口

| 页面/接口 | 主要内容 |
|---|---|
| `/personal`、`GET /reports/personal/daily` | 指定日期个人收入、支出、转出、转入与账户变动明细 |
| `GET /reports/personal/summary` | 个人资产、收入、支出、转账/资产变动汇总 |
| `GET /reports/personal/trend` | 个人月度收支趋势 |
| `GET /reports/personal/by-category` | 个人支出分类占比 |
| `/family-dashboard`、`GET /reports/family/summary` | 家庭收入、支出、结余、总资产、预算和最近流水 |
| `GET /reports/family/trend` | 家庭月度收支趋势 |
| `GET /reports/family/by-category` | 家庭支出分类占比 |
| `GET /reports/family/by-member` | 成员收入、支出、资产及转账变动对比 |

### 8.3 聚合规则与测试

个人资产为该成员未销户账户的余额之和；个人收入、支出按 `beneficiary_member_id` 聚合。家庭资产为全部未销户账户余额之和；家庭收入、支出仅聚合 `transactions`。`transfers` 不参与任何收入、支出、结余和预算运算，但作为个人转账/资产变动及家庭内部资金流动单独查询。个人查询接口必须根据 JWT 用户和请求中的 `family_id` 自动解析成员，不接受前端传入任意成员 ID。

报表在无数据时返回零值指标和空序列，前端展示空状态。测试应验证个人与家庭数据隔离、转账不污染收支、销户账户不计入当前资产，以及成员对比按资金归属人与账户所属人使用对应口径。

## 9. 预算模块

### 9.1 完成内容

- 管理员设置月度总预算和支出分类预算。
- 计算已用、剩余、使用率与预警等级；支持复制上月预算。

### 9.2 数据表与接口

```text
monthly_budgets(id, family_id, month, total_amount, created_at, updated_at)
category_budgets(id, family_id, month, category_id, amount, created_at, updated_at)
```

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| `GET` | `/api/v1/budgets/{month}?family_id={id}` | 成员 | 查询预算和执行情况 |
| `PUT` | `/api/v1/budgets/{month}` | 管理员 | 保存总预算与分类预算 |
| `POST` | `/api/v1/budgets/{month}/copy-from-previous` | 管理员 | 复制上月预算草稿 |

### 9.3 页面、计算与测试

预算页使用月选择器、统计卡片和分类预算表。`used_amount` 为当月同家庭、同分类、`type=EXPENSE` 的流水金额之和；不统计收入、转账和销户账户与否无关的历史支出。使用率小于 80% 为正常，80% 至 100% 为预警，超过 100% 为超支；预算为 0 时使用率按 0 处理。测试覆盖支出修改后重新聚合、转账不计入预算、普通成员无保存权限。

确认导入前再次执行去重与家庭、账户、分类、成员校验。重复判定键固定为“账户 + 日期 + 金额 + 备注”：日期取发生日期，金额格式化为两位小数，备注首尾空白忽略。系统同时检查数据库已有流水和当前批次内重复行，重复行标记为 `DUPLICATE` 并默认跳过。批量写入正式流水和账户余额更新必须在一个事务中完成；任一有效行无法写入则整体回滚并标记失败。测试覆盖 CSV、XLSX、缺失列、非法金额、数据库重复、批次内重复、销户账户和数据库异常回滚。

## 11. 流水导出模块

### 11.1 完成内容

- 管理员按家庭、成员、账户、日期和流水类型筛选收支流水并导出。
- 提供 CSV 与 Excel（`.xlsx`）两种格式，且导出数据遵守家庭隔离与权限规则。

### 11.2 接口、列与测试

`GET /api/v1/exports/transactions?family_id={id}&from=YYYY-MM-DD&to=YYYY-MM-DD&format=csv|xlsx`。

导出列至少包含：发生日期、类型、金额、账户、账户所属人、分类、资金归属人、录入人、备注和创建时间。后端根据查询结果使用 `openpyxl` 在内存 `BytesIO` 中生成 XLSX，通过 `StreamingResponse` 返回，响应头为 `Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` 和 `Content-Disposition: attachment; filename*=UTF-8''...xlsx`。前端 Axios 设置 `responseType: 'blob'`，收到 Blob 后创建 `URL.createObjectURL(blob)`，通过临时 `<a download>` 触发下载，完成后调用 `URL.revokeObjectURL`；若响应为错误 JSON Blob，则先读取文本并按统一错误格式提示。CSV 同样以 Blob 下载并使用 UTF-8 BOM。普通成员或不属于当前家庭的用户返回 403；测试应验证格式选择、中文内容、日期筛选、成员筛选、Blob 下载和越权拦截。

## 12. family_id 传递与个人查询约定

### 12.1 传递规则

- 客户端全局状态只保存 `currentFamilyId`，不设置 `X-Family-Id` 等自定义请求头。
- GET 查询接口统一使用查询参数，例如 `GET /api/v1/accounts?family_id=12`、`GET /api/v1/reports/personal/summary?family_id=12`。
- POST、PUT、PATCH 写接口统一在 JSON 请求体中携带 `family_id`；文件导入在 `multipart/form-data` 中携带 `family_id` 字段。
- 资源详情和 DELETE 可以只传资源 ID，由后端先反查资源的 `family_id` 再进行家庭成员和相关成员权限校验。

### 12.2 个人与家庭查询

- 家庭统计接口使用 `scope=family` 或 `/reports/family/*`，汇总当前 `family_id` 下全部成员数据。
- 个人接口使用 `/reports/personal/*` 或 `scope=personal`，必须同时传 `family_id`；后端通过 JWT 的 `user_id` 查询该家庭的 `family_member_id`，强制过滤当前成员的收入/支出及其转账参与记录。
- 前端不传任意 `member_id` 作为个人身份依据；管理员查看某成员对比时使用家庭报表的明确 `member_id` 参数，并由后端校验该成员属于当前家庭。

## 13. 模块依赖与实现顺序

```text
认证与用户
  -> 家庭与成员
    -> 账户、分类
      -> 收入/支出流水
        -> 内部转账、预算、个人/家庭首页与报表
          -> 外部账单导入、流水导出
```

账户和分类是收支流水的前置条件；收支流水与内部转账共同提供个人资产变化；预算、报表、导入和导出均依赖已稳定的收支流水规则。任何后续扩展不得改变本设计中个人与家庭统计、销户和内部转账的既定口径。
