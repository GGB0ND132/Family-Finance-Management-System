### 1.2 产品定位

本系统是一个独立的第三方记账 Web 应用。系统不连接支付平台，不执行支付或扣款，只负责记录用户手动录入的账目，以及用户从微信、支付宝等软件导出的 CSV/Excel 账单导入后的整理、归类和统计。

系统同时提供两种观察视角：

- **个人视角：** 当前成员的单日流水、个人账户、个人资产、个人收入/支出及个人报表。
- **家庭视角：** 当前家庭全部成员的总收支、总资产、家庭预算、成员对比和家庭报表。
- 个人首页和家庭首页是两个独立入口，首页顶部不提供个人/家庭视角切换按钮；收支、转账、预算、账户、报表、导入和导出页面分别提供个人/家庭范围按钮。

## 2. 建设目标

1. 让用户快速记录每笔收入、支出和家庭内部转账。
2. 明确保存账户所属人、收入获得人、支出消费人和转账双方。
3. 支持从个人和家庭两个层面查询任意一笔资金的来源、去向和责任人。
4. 支持微信、支付宝等软件导出账单的 CSV/Excel 导入，而不是实时平台同步。
5. 提供个人单日流水、个人资产、家庭收支和预算报表，且统计口径清晰不重复计算。

## 3. 系统范围

### 3.1 本期实现范围

- 用户注册、登录、退出、修改个人信息和密码。
- 家庭创建、邀请码加入、家庭成员和角色管理。
- 账户管理：新增、编辑、查询和删除/销户；每个账户必须有所属成员。
- 默认收支分类和自定义分类管理。
- 收入、支出和账户间转账记录。
- 个人首页：当前成员单日流水、个人账户余额、个人资产变化和个人统计。
- 家庭首页：家庭总收支、家庭总资产、成员对比、预算进度和家庭统计。
- 个人和家庭月度总预算、可选分类预算和预算预警；个人预算不存在时总预算及分类预算默认为 0，并可按需添加预算分类。
- 从外部软件导出的 CSV/Excel 账单导入，提供字段映射、预览和确认写入。
- 流水导出，格式可选 CSV 或 Excel。

### 3.2 明确不实现的内容

- 支付、转账支付、自动扣款、充值或提现。
- 连接微信、支付宝、银行等平台的实时账单同步 API。
- 票据识别、OCR、拍照识别或自动读取消费凭证。
- 短信验证码、真实身份认证和银行卡自动授权。
- 股票、基金、虚拟货币等投资交易和实时行情。
- 复杂审批流、多人分摊结算和企业级财务核算。

## 5. 核心概念与统计口径

### 5.1 账户所属人

每个账户必须绑定一个家庭成员作为**账户所属人**。所属人表示该账户的资产归属者，不等同于当前操作人。例如，管理员可以代成员录入某张银行卡的消费，但银行卡所属人仍是该成员。

### 5.2 流水关联人

每笔收入和支出必须保存以下人员信息：

- **资金归属人/发生人：** 收入的获得人（谁赚取），支出的实际消费人（谁消费）。
- **录入人：** 实际在系统中创建或导入该记录的用户。

两者可以相同，也可以不同。家庭管理员代成员记账时，录入人是管理员，资金归属人仍是实际赚取或消费的成员。

### 5.3 家庭视角统计

- 家庭收入 = 家庭成员所有收入流水之和。
- 家庭支出 = 家庭成员所有支出流水之和。
- 家庭结余 = 家庭收入 - 家庭支出。
- 家庭总资产 = 家庭所有未销户账户的余额之和。
- 家庭内部转账不计入家庭收入、家庭支出或家庭结余；转账前后家庭总资产不变。

### 5.4 个人视角统计

- 个人资产 = 该成员作为账户所属人的账户余额之和。
- 个人收入 = 资金归属人为该成员的收入流水之和。
- 个人支出 = 资金归属人为该成员的支出流水之和。
- 个人首页展示该成员选定日期（默认当天）的收入、支出、转账和账户变动明细。
- 家庭内部转账必须在个人流水中保留，体现转出成员资产减少和转入成员资产增加；转账不重复计入个人收入或个人支出，个人报表单独展示“个人转账/资产变动”。

## 7. 功能需求

### 7.1 认证与用户管理

**FR-01 注册与登录**

- 用户可使用用户名和密码注册、登录和退出。
- 用户名必须唯一，密码长度不得少于 8 位。
- 密码只保存 bcrypt 哈希值，不保存明文。
- 登录成功返回 JWT Access Token；Token 失效后受保护接口返回 401。
- 登录成功后默认进入个人首页；若用户尚未加入任何家庭，则先进入创建/加入家庭页面，完成家庭选择后进入个人首页。

**FR-02 个人信息**

- 用户可查看和修改昵称。
- 用户可修改密码，修改时必须验证旧密码。

### 7.2 家庭与成员管理

**FR-03 家庭管理**

- 已登录用户可以创建家庭，创建者自动成为管理员。
- 用户可以查看自己加入的家庭并切换当前家庭。
- 管理员可以修改家庭名称。

**FR-04 成员管理**

- 管理员可以生成有有效期的邀请码，并使邀请码失效。
- 登录用户可以使用有效邀请码加入家庭。
- 管理员可以查看成员、移除成员、授予或撤销管理员角色。
- 系统必须保证每个家庭至少有一名管理员。

### 7.3 账户管理

**FR-05 账户信息**

- 账户必须包含：账户名称、账户类型、所属家庭、所属成员、初始余额、当前余额、备注和创建时间。
- 账户类型包括现金、银行卡、支付宝、微信、信用卡和其他。
- 账户所属人必须是当前家庭成员；一个成员可以拥有多个账户。
- 账户所属人和账户名称可以编辑，账户编辑不得改变已有流水的历史归属事实。

**FR-06 删除与销户**

- 账户不提供“启用/停用”开关，不设置由用户控制的使用状态。
- 没有任何流水或转账记录的账户可以直接删除。
- 已存在流水或转账记录的账户不能物理删除；用户执行删除操作时，系统将其处理为**销户**。
- 账户删除或销户前，当前余额必须为 0.00；若仍有余额，系统提示“账户仍有资金，请先转出后再销户”，并拒绝操作。
- 销户后保留账户、所属人和全部历史记录，不允许再新增收入、支出或转账使用该账户。
- 销户账户不计入当前家庭总资产和个人当前资产，但历史期间的报表仍可查询该账户发生的记录。

### 7.4 分类管理

**FR-07 默认分类**

系统首次创建家庭时自动提供以下默认分类，并允许管理员编辑名称或补充说明：

| 默认分类 | 默认方向 | 说明 |
|---|---|---|
| 餐饮 | 支出 | 日常餐饮消费 |
| 住宿 | 支出 | 酒店、短租等住宿 |
| 交通 | 支出 | 公交、地铁、打车、加油等 |
| 住房 | 支出 | 房租、物业、装修等 |
| 购物 | 支出 | 日用品和商品购买 |
| 娱乐 | 支出 | 电影、游戏、旅游娱乐等 |
| 医疗 | 支出 | 看病、药品和医疗服务 |
| 借入 | 收入 | 从他人处借入资金 |
| 借出 | 支出 | 借给他人资金 |
| 还款 | 支出 | 偿还借款或贷款 |
| 收款 | 收入 | 非工资类收款 |
| 工资 | 收入 | 工资、薪金 |
| 奖金 | 收入 | 奖金、补贴和奖励 |

**FR-08 自定义分类**

- 管理员可以新增自定义收入或支出分类。
- 分类必须声明收入或支出方向；流水类型必须与分类方向一致。
- 已经被流水或预算使用的分类不得物理删除，可执行删除请求并由系统保留历史引用。

### 7.5 收入、支出与转账

**FR-09 收入和支出流水**

- 新增收入或支出必须填写：金额、账户、分类、发生时间（精确到分钟）、资金归属人/发生人、录入人和备注。
- 资金归属人必须是当前家庭成员；录入人默认为当前登录用户。
- 支出流水的资金归属人表示实际消费人；收入流水的资金归属人表示实际赚取或获得人。
- 收支页面提供个人/家庭范围按钮；个人范围按当前成员作为资金归属人查询，家庭范围按当前家庭全部流水查询。支持按时间、类型、账户、账户所属人、分类、资金归属人、录入人和金额范围筛选，并支持分页。
- 新增收入增加所属账户余额；新增支出减少所属账户余额。
- 修改或删除流水后，账户余额、个人统计、家庭统计和预算使用额必须同步正确。
- 普通成员可以编辑或删除与自己相关的流水：收入/支出中账户所属人为自己、资金归属人为自己或录入人为自己；家庭内部转账中转出方、转入方或录入人为自己。转账双方均可编辑和删除该转账；管理员可以维护当前家庭全部流水。

**FR-10 家庭内部转账**

- 转账必须填写转出账户、转入账户、金额、发生时间（精确到分钟）、转出方成员、转入方成员、录入人和备注。转账方向由转出账户和转入账户推导，不设置独立方向字段。
- 转出账户和转入账户必须属于同一家庭且不能相同。
- 转出账户余额减少，转入账户余额增加；家庭总资产保持不变。
- 转账页面提供个人/家庭范围按钮；个人范围显示当前成员作为转出方或转入方的转账，家庭范围显示当前家庭全部转账。家庭内部转账不计入家庭收入、家庭支出、家庭结余或家庭预算。
- 转账必须在个人流水中可查询：转出方显示个人资产减少，转入方显示个人资产增加。
- 转账不重复计入个人收入或个人支出，个人报表中单独统计转账和资产变动。
- 转账双方成员均拥有该转账的编辑和删除权限；与双方无关的普通成员无权修改，管理员可以维护全部转账。
- 转账的两次余额变更、人员关联和转账记录必须在一个数据库事务中完成。

### 7.6 个人首页与家庭首页

**FR-11 个人首页**

- 默认展示当前成员当天的收入、支出、转账和账户变动流水。
- 支持切换日期查看其他日期的个人流水。
- 展示个人账户余额、个人总资产、当日收入、当日支出和当日转账。
- 展示个人收入来源、个人支出分类和个人月度趋势。

**FR-12 家庭首页**

- 展示当前家庭当月总收入、总支出、结余和家庭总资产。
- 展示家庭分类支出、月度趋势、成员收入/支出对比和预算执行情况；个人报表不展示成员对比。
- 家庭首页不将内部转账计入收支，但可以单独展示家庭内部资金流动。
- 家庭成员均可查看家庭报表；是否允许编辑数据由具体权限规则决定。

### 7.7 月度预算

**FR-13 预算设置**

- 预算页面提供个人/家庭范围按钮。当前成员可以设置个人某年某月的总预算和支出分类预算，管理员可以设置家庭某年某月的总预算和支出分类预算。
- 个人预算记录不存在时，系统以总预算 0、分类预算为空（各预算金额按 0 处理）初始化；用户可以选择支出分类添加预算项目，也可以删除当前月份的预算项目。删除预算项目不删除全局分类或历史流水。
- 预算页可以快捷创建新的预算分类项目；该操作只创建或选择当前月份的预算项目，不改变全局分类。若要创建可供所有月份使用的全局收支分类，仍需在分类管理中按权限操作。
- 系统展示预算金额、已用金额、剩余金额和使用率。
- 预算已用金额按范围统计：个人范围只统计当前成员作为资金归属人的支出流水，家庭范围统计当前家庭全部支出流水；两种范围均不统计收入和家庭内部转账。
- 使用率达到 80% 时预警，超过 100% 时标记为超支。
- 支持复制同一范围的上月预算作为当前月预算草稿。

### 7.8 外部账单导入

**FR-14 文件来源与格式**

- 系统不调用微信、支付宝或银行的实时账单 API。
- 用户先从外部软件导出账单文件，再上传到本系统。
- 支持 CSV 和 Excel（`.xlsx`）文件；具体字段根据来源文件在导入页面映射。

**FR-15 导入流程**

1. 用户选择家庭、目标账户和账单来源。
2. 上传 CSV/Excel 文件，系统解析表头和明细行。
3. 用户将来源字段映射为发生时间、金额、收支方向、分类、对方/备注等系统字段；发生时间精确到分钟。
4. 系统按“账户 + 发生时间（精确到分钟）+ 金额 + 备注”判定重复，展示重复行、无法识别行和待确认分类；时间按标准化后的分钟值比较，金额按两位小数标准化，备注去除首尾空白后比较。来源文件只有日期没有时间时，默认补充为当天 `00:00` 并提示用户。
5. 用户确认后批量写入流水，并为每条记录补充资金归属人和录入人。
6. 导入失败时返回行号和原因，已成功写入的批次必须可回滚或整体不提交。

### 7.9 流水导出

**FR-16 导出格式**

- 用户可以按个人/家庭范围、成员、账户、时间范围和流水类型筛选导出内容；个人范围只能导出当前成员有权查看的数据，家庭范围遵守当前家庭权限。
- 导出格式由用户选择 CSV 或 Excel（`.xlsx`）。
- 导出字段至少包括：发生时间（精确到分钟）、类型、金额、账户、账户所属人、分类、资金归属人、录入人、备注和创建时间（精确到分钟）。
- 导出内容必须遵守当前用户权限和家庭数据隔离规则。
- XLSX 文件由后端生成并以文件流返回，前端以 Blob 接收并触发下载，不在前端重新拼装报表数据。

## 8. 业务规则

| 编号 | 规则 |
|---|---|
| BR-01 | 账户必须绑定一个当前家庭成员作为所属人。 |
| BR-02 | 每笔收入和支出必须绑定资金归属人/发生人及录入人。 |
| BR-03 | 账户、分类、流水、转账和成员必须属于同一个家庭。 |
| BR-04 | 金额必须大于 0；后端使用 `Decimal`，MySQL 使用 `DECIMAL(12,2)`。 |
| BR-05 | 收入增加账户余额，支出减少账户余额。 |
| BR-06 | 家庭内部转账不计入家庭收支和预算，转账前后家庭总资产不变。 |
| BR-07 | 家庭内部转账必须体现转出成员和转入成员的个人资产变化，并保留个人流水。 |
| BR-08 | 个人收入/支出统计按资金归属人计算，录入人用于操作审计和相关流水编辑权限判断。 |
| BR-09 | 账户删除或销户前余额必须为 0；无历史记录且余额为 0 时可删除，有历史记录且余额为 0 时删除请求转为销户，保留历史数据且不可产生新流水。 |
| BR-10 | 系统不提供账户启用/停用控制；销户是删除历史账户的保护性处理。 |
| BR-11 | 默认分类为餐饮、住宿、交通、住房、购物、娱乐、医疗、借入、借出、还款、收款、工资、奖金，并允许自定义分类。 |
| BR-12 | 外部账单只能通过用户上传 CSV/Excel 文件导入，不承诺实时平台同步。 |
| BR-13 | 导入批次应具备预览、重复识别、错误提示和整体提交/回滚能力。 |
| BR-14 | 管理员不能移除最后一名管理员，也不能直接移除自己。 |
| BR-15 | 导入重复判定键为“账户 + 发生时间（精确到分钟）+ 金额 + 备注”，同时检查数据库已有流水和当前导入批次内重复行。 |
| BR-16 | 普通成员可编辑与自己相关的收支或内部转账；收支相关条件包括账户所属人、资金归属人或录入人为自己，内部转账的转出方和转入方均可编辑。 |
| BR-17 | 收支和转账发生时间必须精确到分钟；前端和后端均校验时间格式，接口统一使用带时区 ISO 8601 时间。 |
| BR-18 | 个人预算不存在时按总预算 0、分类预算为空处理；预算页添加或移除分类只影响当前预算项目，不删除全局分类。 |

## 9. 非功能需求

### 9.1 安全性

- 受保护接口使用 JWT 认证，后端实施角色和家庭归属校验。
- 所有家庭查询必须校验当前用户是家庭成员；不能只依赖前端传入的 `family_id`。
- 不使用自定义家庭请求头：GET 查询接口在查询参数中传入 `family_id`，POST/PATCH/PUT 写接口在请求体中传入 `family_id`；后端始终校验其归属。个人查询也要求 `family_id` 用于选择家庭，但成员身份由 JWT 对应的 `user_id` 在后端解析，不接受前端伪造 `member_id`。
- 数据库密码、JWT 密钥等敏感信息写入 `.env`，不得提交到版本库。
- 导入文件需限制大小和格式；解析失败不能执行半批次写入。
- 系统异常不向客户端暴露 SQL 语句、数据库密码和完整堆栈。

### 9.2 性能与可靠性

- 流水列表默认每页 20 条，最大每页 100 条。
- 账户余额变更、转账和账单批量导入使用事务。
- 本地测试数据量达到 10 万条流水时，分页查询不应返回全表。
- 报表查询按家庭、月份、账户所属人和资金归属人建立必要索引。

### 9.3 易用性与可维护性

- 前端采用 Ant Design，收入、支出、转账表单根据类型动态展示相关字段。
- 个人首页与家庭首页使用明确标题和统计口径，避免用户误解转账数据；首页顶部不显示个人/家庭切换按钮。
- 收支、转账、预算、账户、报表、导入和导出页面均提供个人/家庭范围按钮，并在前端通过 URL `scope` 参数保持当前范围；后端根据 JWT、家庭归属和范围再次校验并过滤数据。
- 前端负责输入格式、必填项、金额范围、时间精度和权限提示，后端 Schema、Service、数据库约束负责最终校验；前端绕过或伪造参数时后端必须拒绝。
- 导入页面必须显示字段映射、预览、重复判定结果和错误行；导出页面必须提供 CSV/Excel 选择，XLSX 由后端生成后以前端 Blob 下载。
- 后端通过 FastAPI 自动生成 Swagger 文档，数据库变更通过 Alembic 管理。

## 10. 验收标准

1. 用户可注册、登录、创建家庭并邀请成员加入。
2. 管理员可创建账户并为账户指定所属成员；账户信息可编辑。
3. 账户只有在余额为 0 时才能删除或销户；无历史记录账户可以删除，有历史记录账户执行删除后转为销户，历史流水仍可查询且不能新增记录。
4. 默认分类完整包含餐饮、住宿、交通、住房、购物、娱乐、医疗、借入、借出、还款、收款、工资、奖金，并可新增自定义分类。
5. 每笔收入和支出都能查到资金由谁赚取、由谁消费、由谁录入，以及对应账户所属人。
6. 个人首页默认展示个人单日流水，个人资产和个人报表与家庭统计分开显示。
7. 家庭内部转账后，家庭收支和家庭总资产统计符合规则；转出方和转入方的个人资产变化及转账流水正确。
8. 用户可以导入外部软件导出的 CSV/Excel 文件，按“账户+日期+金额+备注”完成重复判定，并完成字段映射、预览、错误提示和确认写入。
9. 用户可以选择 CSV 或 Excel 导出流水；XLSX 由后端生成、前端 Blob 下载，导出内容包含账户所属人、资金归属人和录入人。
10. Swagger 可访问，核心页面和接口可完成“登录 -> 个人记账 -> 家庭记账 -> 转账 -> 预算 -> 报表 -> 导入/导出”的演示。
