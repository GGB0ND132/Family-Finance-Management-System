# 家庭收支管理系统

需求规格说明与系统架构设计

**文档版本：** v2.0  
**编写日期：** 2026-09-01  
**适用范围：** 软件开发实践 2 课程设计

## 1. 项目概述

### 1.1 项目背景

家庭成员的现金、银行卡、移动支付账户和信用卡通常分散管理，容易出现账目遗漏、预算失控和家庭成员之间信息不一致的问题。本系统提供一个家庭共享账本，用于记录收支、管理账户、设置月度预算并生成统计报表。

### 1.2 建设目标

1. 提供简单、快速、可追溯的收入和支出记录能力。
2. 统一管理家庭账户和账户之间的转账。
3. 通过月度预算和预警帮助家庭控制支出。
4. 通过统计图表展示家庭收入、支出、结余和资产变化。
5. 形成完整的需求、设计、实现、测试和用户手册材料，满足课程交付要求。

### 1.3 产品边界

课程版本只处理用户主动录入或导入的账目，不连接真实银行和第三方支付平台，不执行真实扣款。以下内容作为后续扩展，不纳入第一版验收：短信验证码、银行卡自动同步、在线支付、投资行情、AI 票据识别和复杂审批流。

## 4. 功能需求

### 4.1 认证与用户模块（FR-AUTH）

- 支持用户注册、登录、退出和修改密码。
- 用户名和邮箱（如启用）必须唯一；密码长度不少于 8 位。
- 密码使用 bcrypt 哈希保存，数据库不得保存明文密码。
- 登录成功返回 Access Token；受保护接口必须携带 `Authorization: Bearer <token>`。
- Token 过期或无效时返回 HTTP 401，前端跳转到登录页。

### 4.2 家庭与成员模块（FR-FAMILY）

- 登录用户可以创建家庭，创建者自动成为管理员。
- 管理员可以生成邀请码、使邀请码失效和查看家庭成员。
- 用户可以通过有效邀请码加入家庭，并可以在自己加入的多个家庭之间切换。
- 管理员可以移除成员、将普通成员设为管理员或撤销管理员权限。
- 至少保留一名管理员；管理员不能直接移除自己。
- 所有家庭业务数据必须带有 `family_id`，服务端按成员关系过滤。

### 4.3 账户模块（FR-ACCOUNT）

- 支持现金、银行卡、支付宝、微信、信用卡和其他账户类型。
- 账户信息包括名称、类型、初始余额、当前余额、备注、状态和创建时间。
- 支持新增、编辑、查看和停用账户。
- 有流水或转账记录的账户不能物理删除，只能停用。
- 信用卡账户允许出现负余额，并在首页单独展示负债。

### 4.4 分类模块（FR-CATEGORY）

- 分类区分收入分类和支出分类，不能混用。
- 系统初始化默认分类：工资、奖金、兼职、餐饮、交通、住房、水电、购物、医疗、教育、娱乐和其他。
- 管理员可以新增、编辑、停用自定义分类。
- 已被流水或预算引用的分类不能物理删除。
- 分类可以保存图标和颜色，用于前端图表展示。

### 4.5 收支流水模块（FR-TRANSACTION）

- 支持新增、查看、编辑和删除收入、支出流水。
- 流水必须包括：金额、类型、账户、分类、发生日期、备注、记录人和创建时间。
- 金额必须大于 0，金额在数据库使用 `DECIMAL(12,2)`，禁止使用浮点数保存金额。
- 收入只能选择收入分类，支出只能选择支出分类。
- 支持按日期范围、类型、分类、账户、记录人和金额范围筛选，列表必须分页。
- 新增收入增加账户余额；新增支出减少账户余额。
- 修改或删除流水时，服务端先撤销原余额影响，再应用新记录影响，并在同一事务内提交。
- 普通成员默认只能编辑或删除自己创建的流水；管理员可以维护当前家庭全部流水。

### 4.6 转账模块（FR-TRANSFER）

- 支持在同一家庭的两个账户之间转账。
- 转账必须记录转出账户、转入账户、金额、日期、备注和操作人。
- 转出账户余额减少，转入账户余额增加；转账不计入收入、支出和预算。
- 转账记录写入与余额更新必须使用同一数据库事务，任一步失败则全部回滚。
- 转出账户与转入账户不能相同，金额必须大于 0。

### 4.7 月度预算模块（FR-BUDGET）

- 管理员可以按年月设置家庭总预算和支出分类预算。
- 系统计算预算金额、已用金额、剩余金额和使用率。
- 使用率达到 80% 显示预警，超过 100% 显示超支。
- 支持复制上月预算，复制后允许单独修改。
- 预算统计只包含支出流水，不包含收入和转账。

```text
分类预算使用率 = 当月分类支出 / 分类预算 * 100%
剩余预算 = 分类预算 - 当月分类支出
月度结余 = 当月总收入 - 当月总支出
```

### 4.8 首页与报表模块（FR-REPORT）

- 首页展示本月收入、本月支出、本月结余、家庭总资产、预算进度和最近流水。
- 提供按月切换的收入/支出趋势图。
- 提供支出分类占比图和分类明细表。
- 提供家庭成员支出对比图。
- 提供账户余额汇总和超支分类列表。
- 所有金额统一按两位小数展示，报表查询必须限定当前家庭。

### 4.9 数据导出模块（FR-EXPORT）

- 管理员可按日期范围或月份导出 CSV 流水。
- 导出字段至少包括日期、类型、金额、账户、分类、记录人和备注。
- 导出内容只包含当前家庭数据，响应类型为 `text/csv; charset=utf-8`。

### 4.10 定期账单模块（扩展 FR-RECURRING）

- 支持每周、每月、每年固定收支规则。
- 到期后生成“待确认流水”，确认后才影响账户余额。
- 规则支持启用、停用、编辑和查看下次执行时间。

## 5. 非功能需求

### 5.1 安全性

- 所有受保护接口使用 JWT 鉴权，权限判断在后端完成。
- 每次查询和修改都验证用户是否属于目标家庭，不能仅依赖前端传入的 `family_id`。
- JWT 密钥、数据库密码和 CORS 配置通过 `.env` 注入，不提交真实密钥。
- 统一处理 400、401、403、404、409 和 500 错误，生产环境不返回数据库堆栈。
- 如实现消费凭证上传，限制 MIME 类型、文件大小和存储路径。

### 5.2 性能与可靠性

- 流水列表必须分页，默认页大小 20，最大页大小 100。
- `family_id`、`occurred_at`、`type`、`category_id` 和 `account_id` 建立必要索引。
- 余额更新、转账和流水修正使用事务。
- 在 10 万条测试流水规模下，普通分页接口目标响应时间不超过 1 秒（本地开发环境以测试结果为准）。

### 5.3 可维护性

- 使用模块化目录和类型化 Pydantic Schema。
- 数据库结构只通过 Alembic 迁移修改。
- 所有 API 自动出现在 `/docs` Swagger 页面。
- 关键服务逻辑编写单元测试，核心接口编写集成测试。

## 6. 总体架构

```text
浏览器
  |
  | React SPA / JSON / JWT
  v
Nginx（可选：静态文件与反向代理）
  |
  v
FastAPI
  ├─ Router：路由、参数解析、响应码
  ├─ Dependency：数据库会话、当前用户、家庭权限
  ├─ Service：余额、预算、转账等业务规则
  ├─ Repository：SQLAlchemy 查询与持久化
  └─ Schema：Pydantic 输入/输出模型
  |
  v
SQLAlchemy 2.x + PyMySQL
  |
  v
MySQL 8（InnoDB、utf8mb4）
```

前端负责页面渲染、交互和请求状态；后端负责鉴权、家庭隔离、金额计算和事务；数据库负责关系约束、索引和持久化。

## 9. 数据模型设计

| 表 | 关键字段 | 约束/说明 |
|---|---|---|
| `users` | `id, username, email, password_hash, nickname, created_at` | 用户名唯一，密码哈希 |
| `families` | `id, name, owner_id, invite_code, invite_expires_at` | 家庭和邀请码 |
| `family_members` | `family_id, user_id, role, joined_at` | `(family_id,user_id)` 唯一 |
| `accounts` | `id, family_id, name, type, initial_balance, current_balance, status` | 金额 `DECIMAL(12,2)` |
| `categories` | `id, family_id, name, type, color, status` | `(family_id,name,type)` 唯一 |
| `transactions` | `id, family_id, account_id, category_id, user_id, type, amount, occurred_at, remark` | 收入/支出流水 |
| `transfers` | `id, family_id, from_account_id, to_account_id, user_id, amount, occurred_at` | 转账，不进收支统计 |
| `budgets` | `id, family_id, month, category_id, amount` | `(family_id,month,category_id)` 唯一 |
| `recurring_rules` | `id, family_id, type, account_id, category_id, amount, cycle, next_run_at, status` | 定期账单扩展 |
| `attachments` | `id, transaction_id, file_path, mime_type, created_at` | 凭证扩展 |

### 9.1 关系与一致性

- `family_members` 是用户与家庭的多对多关联表。
- 账户、分类、流水、预算和转账均通过 `family_id` 隔离。
- 外键使用 InnoDB，删除策略优先采用停用或软删除，保留历史账目。
- 服务层创建流水前必须校验账户、分类和当前家庭一致。
- 金额使用 `DECIMAL(12,2)`，Python 侧使用 `Decimal`。

|---|---|---|

| `POST` | `/categories` | 新增分类 |
| `GET` | `/transactions` | 分页查询流水 |
| `POST` | `/transactions` | 新增收入或支出 |
| `PATCH` | `/transactions/{id}` | 修改流水 |
| `DELETE` | `/transactions/{id}` | 删除流水 |
| `POST` | `/transfers` | 创建转账 |
| `GET` | `/budgets/{month}` | 查询月份预算 |
| `PUT` | `/budgets/{month}` | 保存月份预算 |
| `GET` | `/reports/summary?month=YYYY-MM` | 首页汇总 |
| `GET` | `/reports/trend?from=YYYY-MM&to=YYYY-MM` | 收支趋势 |
| `GET` | `/reports/by-category?month=YYYY-MM` | 分类统计 |
| `GET` | `/exports/transactions?from=YYYY-MM-DD&to=YYYY-MM-DD` | 导出 CSV |
| `GET` | `/health` | 服务健康检查 |

成功响应格式：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "request_id": "optional-id"
}
```

错误响应格式：

```json
{
  "code": 40001,
  "message": "金额必须大于0",
  "data": null,
  "request_id": "optional-id"
}
```

建议状态码：`200` 查询或更新成功，`201` 创建成功，`204` 删除成功，`400` 参数错误，`401` 未登录，`403` 无权限，`404` 资源不存在，`409` 唯一性或业务冲突。

## 11. 关键数据流

### 11.1 新增支出

```text
前端提交金额/账户/分类
  -> JWT 认证
  -> 校验当前用户属于家庭
  -> 校验账户和分类属于同一家庭
  -> 开启事务
  -> 写入 transactions
  -> 扣减 accounts.current_balance
  -> 提交事务
  -> 返回流水和最新余额
```

### 11.2 转账

```text
校验金额和两个账户
  -> 开启事务
  -> 锁定两个账户记录（必要时使用 SELECT ... FOR UPDATE）
  -> 转出账户 - amount
  -> 转入账户 + amount
  -> 写入 transfers
  -> 提交；异常则回滚全部操作
```

### 11.3 报表

报表服务只读取当前家庭、指定月份的已生效流水，使用 SQL 聚合收入、支出、分类和成员数据；转账表不参与收入/支出聚合。

## 12. 测试与验收

### 12.1 必测场景

1. 注册、登录和错误密码返回正确结果。
2. 非家庭成员不能读取、修改或删除该家庭数据。
3. 新增收入后账户余额增加，新增支出后余额减少。
4. 转账后两个账户余额正确，家庭总资产保持不变。
5. 修改或删除流水后余额、预算和报表同步变化。
6. 普通成员不能管理成员、修改预算或导出全量数据。
7. 预算达到 80% 显示预警，超过 100% 显示超支。
8. 流水分页、筛选和 CSV 导出内容正确。
9. 停用账户或分类后不能新增关联流水，但历史记录仍可查询。

### 12.2 质量指标

- 核心 API 测试通过率 100%。
- 关键服务（余额、转账、预算）的单元测试覆盖率建议不低于 70%。
- 不出现跨家庭数据泄露。
- Swagger 页面可访问，核心接口有请求和响应说明。
- 演示流程可在 5 分钟内完成：登录、创建家庭、记账、设置预算、查看报表、导出数据。

## 13. 实施阶段

### 阶段一：工程与最小可用版本

完成前后端工程、MySQL 连接、迁移、健康检查、注册登录、家庭和成员、账户、分类及基础收支流水。

### 阶段二：核心业务与展示

完成转账事务、月度预算、首页汇总、趋势图、分类统计、权限完善和 API 测试。

### 阶段三：加分功能与交付

选择定期账单、CSV 导入、凭证上传、移动端响应式布局中的 1 至 3 项，完成测试报告、用户手册、部署说明和演示视频。
